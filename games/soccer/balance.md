# 밸런스 측정

**상태: 현실 계측치 전환 5단계 최종 기준선** (2026-08-02).
측정 도구는 `tools/soccer-sim.js`.

## 측정 조건

조건이 바뀌면 숫자를 비교할 수 없다. 항상 함께 기록한다.

```
명령      node tools/soccer-sim.js -n 200 --seed 1
경기 수   난이도당 200
시드      1 (mulberry32, 같은 파생 청크 시드를 난이도마다 적용)
봇        사람 자리에 aiPlayer + LEVELS[1](보통), isChaser=true
경기 길이 600초 (A안 10분 기본)
화면      1280×720 가로 (회전 없음 — 물리에는 영향 없음)
소요      단계별 표에 기록
```

난이도당 최대 11청크의 독립 VM을 쓰고 기준 시드에서 파생한 같은 청크 시드를
각 난이도에 적용한다. 따라서 전체 측정과 `-l` 단일 난이도 측정의 같은
난이도 결과가 일치하고, 실행 순서도 결과를 바꾸지 않는다.

## 과거 기준선과 해석

0~3단계의 전체 표, 목표 변경 근거와 봇 해석은
[`balance-history.md`](balance-history.md)에 보존한다. 30경기는 빠른 오류
확인에만 쓰며 밸런스 판정은 200경기 이상으로 한다. 봇 수치는 사람 승률의
예측값이 아니라 같은 조건의 변경 전후 회귀 감지값이다.

## 재측정 시점

`roadmap.md` 의 각 단계가 끝날 때마다 같은 조건으로 다시 돌린다.
앞 단계가 승률을 바꿔놓기 때문이다.

구현 단계가 물리나 경기 흐름을 바꾸면 직전 표는 과거 기준선이 된다.

## 리뷰 A — 측정 도구 복구

2026-08-01 strict 실행을 복구했다. 시드 주입과 게임 소스 실행을 분리해
게임의 `'use strict'` 지시어를 보존하고, 셀프테스트가 strict 여부를 직접
검사한다. 수정 후 기준 팀 200경기는 수정 전과 모든 수치가 같았다.

| 구분 | 쉬움 | 보통 | 어려움 | 통합 총득점 |
|---|---:|---:|---:|---:|
| 수정 전 | 82.0% | 56.5% | 23.5% | 5.45 |
| strict 복구 후 | 82.0% | 56.5% | 23.5% | 5.45 |

리뷰 B에서 카드·체력을 킥오프마다 초기화하던 코드를 제거한 뒤에도 같은
200경기 값이 재현됐다. 측정 봇은 스프린트 입력을 내지 않아 체력을 쓰지
않으므로, 상태 유지는 득점·하프타임을 통과하는 셀프테스트로 검증한다.

리뷰 C 200경기는 오프사이드가 쉬움/보통/어려움 `0.00/0.63/0.35`회,
승률 `82.0/44.0/28.0%`, 통합 총득점 `5.35`였다. 보통 승률은 D에서 튜닝한다.

기존 `--sweep-speed` 표 두 개는 4단계에서 제거된 `LEVELS[].speed`를
바꿔 측정한 값이라 무효다. 도구를 실제 이동 코드가 읽는
`OPPONENT_SPEED_MUL[1]` 축으로 고치고 다시 측정했다.

```
명령      node tools/soccer-sim.js --sweep-speed -n 200 --seed 1
범위      보통 1P 상대 속도 배수 0.84~0.94, 0.01 간격

팀/전술   골목 FC 대 골목 FC, 기본 전술
```

### 5단계 최종 기준선

위 측정 조건으로 쉬움·보통 200경기를 확정하고, 어려움은 마지막 `gk`
조정 뒤 같은 명령의 `-l 2`로 200경기를 다시 쟀다. 최종값은
`LEVELS gk=0.85/1.15/1.55`, `HUMAN_ASSIST=1.00/0.35/0`이다.

| 난이도 | 승/무/패 | 승률 (95% CI) | 총득점 | 슛/경기 | 성공률 |
|---|---:|---:|---:|---:|---:|
| 쉬움 | 159/38/3 | 79.5% (73.4~84.5) | 2.58 | 22.23 | 11.5% |
| 보통 | 105/45/50 | 52.5% (45.6~59.3) | 2.60 | 25.34 | 10.1% |
| 어려움 | 44/44/112 | 22.0% (16.8~28.2) | 2.82 | 28.02 | 10.0% |

통합 총득점은 2.67이다. 세 승률 목표 80/53/23%가 모두 95% CI 안이며,
난이도별 총득점 2~3과 슛 성공률 10~15%를 모두 만족한다. 비슛 득점은
각각 1.0/1.2/0.2%로 50% 이하이고 득점 분류 항등식도 통과했다.

| 난이도 | 평균 | 최고 | 걷기 | 조깅 | 달리기 | 스프린트 | 전반→후반 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 쉬움 | 7.07 | 31.73 | 63.2% | 32.5% | 4.1% | 0.2% | 7.30→6.83 |
| 보통 | 7.33 | 31.72 | 60.2% | 35.6% | 4.0% | 0.2% | 7.65→7.00 |
| 어려움 | 7.36 | 31.72 | 60.5% | 35.1% | 4.2% | 0.2% | 7.71→7.01 |

6·20분 완주·비례 스모크는 보통 30경기에서 총득점 1.70/5.93,
슛 성공률 모두 11.6%였다. 10분 2.60을 기준으로 시간에 따라 증가한다.

## 도구 사용법

```bash
node tools/soccer-sim.js              # 난이도당 30경기 (빠른 확인용)
node tools/soccer-sim.js -n 200       # 밸런스 변경 시
node tools/soccer-sim.js -l 1 -n 200  # 보통만
node tools/soccer-sim.js --seed 7     # 다른 시드로 재확인
node tools/soccer-sim.js --bot 2      # 사람 자리 봇을 어려움 수준으로
node tools/soccer-sim.js -l 1 -n 30 --match-sec 360 # 경기 길이 스모크
node tools/soccer-sim.js --gk-reach 1.4 # 골키퍼 도달 배수 비교
node tools/soccer-sim.js --self-test    # 오프사이드·파울 시나리오
node tools/soccer-sim.js --sweep-speed # 보통 상대 속도 배수별 200경기 스윕
```

일반 측정은 난이도·청크마다, 스윕은 speed 값마다 독립 VM을 쓴다.
`--seed`를 바꾼 결과의 신뢰구간이 겹치지 않을 정도로 흔들리면 표본이나
모델의 안정성을 다시 검토한다.
