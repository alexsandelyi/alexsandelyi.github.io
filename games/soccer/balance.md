# 밸런스 측정

**상태: 현실 계측치 전환 측정 중** (2026-08-02). 추측이 아니라 실행 결과다.
측정 도구는 `tools/soccer-sim.js`.

## 측정 조건

조건이 바뀌면 숫자를 비교할 수 없다. 항상 함께 기록한다.

```
명령      node tools/soccer-sim.js -n 200 --seed 1
경기 수   난이도당 200
시드      1 (mulberry32, 난이도마다 같은 상태로 다시 초기화)
봇        사람 자리에 aiPlayer + LEVELS[1](보통), isChaser=true
경기 길이 600초 (A안 10분 기본)
화면      1280×720 가로 (회전 없음 — 물리에는 영향 없음)
소요      단계별 표에 기록
```

난이도마다 독립 VM과 같은 초기 시드를 사용한다. 따라서 전체 측정과
`-l` 단일 난이도 측정의 같은 난이도 결과가 일치하고, 실행 순서도 결과를
바꾸지 않는다.

## 과거 기준선과 해석

0~3단계의 전체 표, 목표 변경 근거와 봇 해석은
[`balance-history.md`](balance-history.md)에 보존한다. 30경기는 빠른 오류
확인에만 쓰며 밸런스 판정은 200경기 이상으로 한다. 봇 수치는 사람 승률의
예측값이 아니라 같은 조건의 변경 전후 회귀 감지값이다.

## 재측정 시점

`roadmap.md` 의 각 단계가 끝날 때마다 같은 조건으로 다시 돌린다.
앞 단계가 승률을 바꿔놓기 때문이다.

구현 단계가 물리나 경기 흐름을 바꾸면 직전 표는 과거 기준선이 된다.

## 리뷰 A — 측정 도구 복구

2026-08-01 strict 실행을 복구했다. 시드 주입과 게임 소스 실행을 분리해
게임의 `'use strict'` 지시어를 보존하고, 셀프테스트가 strict 여부를 직접
검사한다. 수정 후 기준 팀 200경기는 수정 전과 모든 수치가 같았다.

| 구분 | 쉬움 | 보통 | 어려움 | 통합 총득점 |
|---|---:|---:|---:|---:|
| 수정 전 | 82.0% | 56.5% | 23.5% | 5.45 |

리뷰 B에서 카드·체력을 킥오프마다 초기화하던 코드를 제거한 뒤에도 같은
200경기 값이 재현됐다. 측정 봇은 스프린트 입력을 내지 않아 체력을 쓰지
않으므로, 상태 유지는 득점·하프타임을 통과하는 셀프테스트로 검증한다.

리뷰 C 200경기는 오프사이드가 쉬움/보통/어려움 `0.00/0.63/0.35`회,
승률 `82.0/44.0/28.0%`, 통합 총득점 `5.35`였다. 보통 승률은 D에서 튜닝한다.

`OPPONENT_SPEED_MUL[1]` 축으로 고치고 다시 측정했다.

| 구분 | 쉬움 | 보통 | 어려움 | 총득점 | 최장 worker |

## 현실 전환 1단계 — 물리 상수와 그리기 분리

상수만 현실 계측치로 바꾸고 밸런스는 조정하지 않았다. 명령은 위 조건의
`node tools/soccer-sim.js -n 200 --seed 1`, 골목 FC끼리 기본 전술이다.

| 난이도 | 승/무/패 | 승률 (95% CI) | 득점 | 실점 | 총득점 |
|---|---:|---:|---:|---:|---:|
| 쉬움 | 136/20/44 | 68.0% (61.2~74.1) | 5.17 | 3.43 | 8.61 |
| 보통 | 133/33/34 | 66.5% (59.7~72.7) | 6.74 | 5.23 | 11.97 |
| 어려움 | 89/34/77 | 44.5% (37.8~51.4) | 6.98 | 6.77 | 13.75 |

통합 총득점은 11.44, 최장 worker는 694.6초였다. 선수 몸집과 골문이
작아진 직후 수비가 사라져 득점이 폭증한다는 예상과 일치한다. 1단계 완료
판정은 물리 상수·직선 속도·충돌 반경·표시 분리이며, 승률과 득점은
5단계 전까지 조정하지 않는다.

### 2단계 카메라 회귀

카메라 40m/26m 고정 줌, 6m 리드와 상시 미니맵 적용 후 같은 200경기를
다시 실행했다. 승·무·패, 득실점, step 수와 모든 판정 횟수가 1단계 표와
정확히 같았다. 최장 worker는 722.3초였다. 화면 크기와 카메라가 물리 결과에
영향을 주지 않음을 확인했다.

### 3단계 이동 행동

걷기·조깅·달리기·스프린트와 AI 체력 소모 적용 후 같은 조건으로 측정했다.
이 단계에서는 승률·득점을 조정하지 않았다.

| 난이도 | 승/무/패 | 승률 | 총득점 | 평균 속도 | 걷기 | 전반→후반 |
|---|---:|---:|---:|---:|---:|---:|
| 쉬움 | 134/26/40 | 67.0% | 4.10 | 7.24 | 63.2% | 7.64→6.84 |
| 보통 | 114/36/50 | 57.0% | 4.41 | 7.49 | 60.8% | 7.88→7.10 |
| 어려움 | 88/26/86 | 44.0% | 5.78 | 7.38 | 62.6% | 7.78→6.98 |

최고속도는 모두 31.73km/h, 최장 worker는 949.9초였다. 이동 완료 조건은
모두 통과했고 밸런스 차이는 5단계로 넘겼다.

## 도구 사용법

```bash
node tools/soccer-sim.js              # 난이도당 30경기 (빠른 확인용)
node tools/soccer-sim.js -n 200       # 밸런스 변경 시
node tools/soccer-sim.js -l 1 -n 200  # 보통만
node tools/soccer-sim.js --seed 7     # 다른 시드로 재확인
node tools/soccer-sim.js --bot 2      # 사람 자리 봇을 어려움 수준으로
node tools/soccer-sim.js --gk-reach 1.4 # 골키퍼 도달 배수 비교
node tools/soccer-sim.js --self-test    # 오프사이드·파울 시나리오
node tools/soccer-sim.js --sweep-speed # 보통 상대 속도 배수별 200경기 스윕
```

일반 측정은 난이도마다, 스윕은 speed 값마다 독립 VM과 같은 초기 시드를
사용한다. `--seed`를 바꾼 결과의 신뢰구간이 겹치지 않을 정도로 흔들리면
표본이나 모델의 안정성을 다시 검토한다.
