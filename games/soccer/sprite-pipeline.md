# 스프라이트 만들기 — 파이프라인·프레임·구현

**상태: 구현 완료** (2026-08-05). 액션 목록과 방향·우선순위 설계는
[player-sprites.md](player-sprites.md) 에 있다. 이 문서는 그림을 어떻게
만들어 게임에 붙였는지다.

## 제작 방식 — C. PNG 시트 `확정` (2026-08-05)

사용자 결정. 프로시저럴(A)·SVG(B)는 버린다.

**그림은 `tools/sprite-gen.py` 가 그린다.** 손으로 픽셀을 찍지 않는다 —
포즈 하나를 고치려고 34장을 다시 그릴 수 없기 때문이다. 스크립트가
사지 각도를 받아 4배 크기로 그린 뒤 축소해 안티에일리어싱을 만든다.

```bash
python tools/sprite-gen.py          # games/soccer/assets/players.png 생성
```

Pillow 만 쓴다. **사이트 의존성은 늘지 않는다** — `tools/` 는 개발 도구라
배포물에 들어가지 않는다 (`soccer-sim.js` 와 같은 위치다).

### 색은 굽지 않는다 — 2레이어

시트는 세로로 2줄이다.

| 줄 | 내용 | 런타임 처리 |
|---|---|---|
| 0 | 유니폼(상의·소매·반바지) **회색조** | 팀 색을 `multiply` 로 곱함 |
| 1 | 머리·팔·다리·축구화·윤곽 | 그대로 겹쳐 그림 |

**`multiply` 를 쓰는 이유**는 일러스트의 접힘과 그림자를 살리기 위해서다.
`source-in` 으로 단색을 부으면 명암이 사라져 평면이 된다. 손으로 그린
포즈는 유니폼이 순백이라 곱해도 팀 색 그대로다 — 두 방식이 한 시트에서
공존한다. `multiply` 는 투명한 곳까지 칠하므로 `destination-in` 으로
알파를 되돌려야 한다.

**틴트는 로드할 때 4벌을 미리 만들어 둔다.** 매 프레임 22명을 오프스크린
합성하면 비싸다. 홈·원정·GK홈·GK원정 4장을 시작할 때 한 번 굽는다.

## 프레임 `확정` (2026-08-05)

총 **34장.** 셀 64px, 시트 2176 × 128.

| 포즈 | 장수 | 비고 |
|---|---|---|
| `idle` | 1 | 손 일러스트 |
| `walk` | 4 | 손 일러스트 2장 + 각각의 좌우 반전. `jog` 도 이걸 쓴다 |
| `run` | **2** | 손으로 그린 일러스트. 좌우 반전 한 쌍 (아래 참조) |
| `kick` | 3 | 준비·임팩트·팔로스루. `pass`/`cross` 공용 |
| `shoot` | 3 | 백스윙이 더 크다 |
| `charge` | 1 | 슛 충전 |
| `tackle` | 3 | 0.22초 안에 3장 ≈ 73ms/장 |
| `block` | 2 | 0.25초 |
| `header` | 3 | |
| `deflect` | 2 | |
| `gk-dive` | 3 | |
| `gk-claim` | 2 | |
| `gk-punt` | 3 | |

### 줄인 것과 그 이유

지름 18~40px 에서 안 보이는 차이는 만들지 않는다.

- **`jog`·`sprint` 는 전용 시트가 없다.** 보폭 차이를 굽는 대신 재생
  속도로 낸다.
- **`pass` 와 `cross` 는 `kick` 을 함께 쓴다.** 팔로스루 높이 차이가
  이 크기에서 구분되지 않는다.
- **`dribble` 전용 에셋은 없다.** 이동 포즈를 그대로 쓴다. 공은 어차피
  `drawBall()` 이 따로 그리므로 발밑에 공이 보인다.
- **`trap` 은 포즈를 두지 않는다.** 드리블의 시작일 뿐이다.
- **지친 상태(`energy <= 0.08`)도 에셋이 없다.** 스프린트가 달리기로
  강등되면 `run` 시트가 느리게 돌아 저절로 표현된다.

`deflect` 는 즉발이지만 **포즈는 남긴다.** 몸에 맞고 튀는 게 보여야
공을 놓친 이유가 전달된다. `poseT` 로 0.15초를 잡아준다.

## 이동 포즈는 손 일러스트다 `확정` (2026-08-08)

사용자가 참고 그림을 주고 `run`·`idle`·`walk` 를 그걸로 교체하라고 했다.
벡터로 그린 이동 포즈가 **수직 톱다운**이라 다리가 어깨에 가려 보폭이 안
보였기 때문이다. 받은 그림은 **위에서 비스듬히 뒤를 본** 각도라
머리 → 등번호 → 반바지 → 다리 → 축구화가 몸 축을 따라 늘어선다.

```bash
python tools/sprite-cutout.py <원본.png> run     # 배경 제거 → sprite-src/
python tools/sprite-cutout.py <원본2.png> stand  # 한 장에 2명이면 자동 분할
python tools/sprite-gen.py                       # 시트에 앉힌다
```

| 포즈 | 원본 | 프레임 |
|---|---|---|
| `idle` | `stand0.png` | 1 (반전 없음) |
| `walk` | `stand0.png` `stand1.png` | 4 (각 원본 + 반전) |
| `run` | `run.png` | 2 (원본 + 반전) |

- **원본은 저장소 안(`tools/sprite-src/`)에 둔다.** 내려받기 폴더에 있으면
  재생성이 안 된다.
- 배경 제거는 **테두리에서 흰색을 타고 들어가는 flood fill** 이다. 밝은
  픽셀을 전부 지우면 흰 축구화에 구멍이 난다.
- 원본은 **위를 향해** 그려져 있다. 생성기가 `+x` 를 향하게 돌린다.
- **반전 프레임은 대칭 동작에만 쓴다.** 걷기·달리기는 두 다리가 번갈아
  나가므로 반전 한 장이 반 주기를 그대로 대신한다.
- 유니폼(파랑)은 색으로 골라내 회색조로 남긴다. 팀 색을 곱해도 명암이 산다.
- **한 장에 인물이 여럿이면 세로 빈 칸으로 나눈다.** 통째로 쓰면 두 명이
  한 스프라이트가 된다.
- **크기 기준은 어깨 폭(`KIT_W`)이다.** 전체 길이로 맞추면 달릴 때 뒤로
  뻗은 다리 때문에 선수가 작아지고 서 있을 때 커진다. 원본마다 그려진
  크기가 달라서 이 기준이 없으면 포즈가 바뀔 때 선수 크기가 튄다.

### 컷아웃 퍼펫은 실패했다 (2026-08-12)

남은 포즈를 원본 없이 만들어 보려고, 서 있는 일러스트를 **부위로 잘라
관절에서 돌리는** 방법을 시험했다. 팔·다리는 연결 요소로 깨끗이 분리됐고
회전도 됐지만, **결과가 `idle` 과 구분되지 않았다.**

이유는 각도다. 원본이 **뒤에서 본** 그림이라 다리를 2D 로 돌려도 몸
실루엣 안에서만 움직인다. 실제 킥은 다리가 공 쪽으로 뻗으며 원근이
바뀌는 동작이라 평면 회전으로는 나오지 않는다. `gk-dive` 만 몸 전체를
65~85° 돌려 쓸 만했다.

부수적으로 크기 기준도 깨졌다. 몸을 통째로 돌리면 유니폼의 가로 폭이
어깨가 아니라 몸 길이가 돼서 `KIT_W` 기준이 무너진다.

**되돌렸다.** 자세별 원본 그림이 있어야 한다.

**아직 킥·태클·헤딩·GK 는 벡터 그림이라 그림체가 섞여 있다.** 같은 방식
으로 바꾸면 통일된다 — 원본만 있으면 `IMPORTED` 에 한 줄 추가하면 되고,
프레임 수와 `POSES` 표는 생성기가 알아서 맞춘다.

되돌아간다. 그림이 없다고 경기가 멈추지는 않는다.

## 겪은 함정

**1. 톱다운인데 반바지를 크게 그렸다.** 어두운 반바지·머리가 상의를 덮어
팀 색이 거의 안 보였다. 위에서 보이는 것은 정수리·어깨·팔뿐이다.

**2. 팔을 상의 색으로 그렸다.** 몸통에 묻혀 실루엣이 덩어리 하나가 됐다.
반팔 소매만 팀 색으로 두고 그 밖은 맨살로 뺐다.

**3. 셀 모서리에서 잘렸다.** 중심에서 제일 멀리 뻗는 것은 태클의 뻗은
발이 아니라 **좌우로 벌린 팔**이다 (`gk-dive` 약 31.8). 회전으로 방향을
내므로 내접원을 넘으면 안 된다. `build()` 가 `check_fit()` 으로 매 셀을
검사해 넘으면 생성을 실패시킨다.

**4. 자유공 킥에 포즈를 안 걸었다.** `kickOwned()` 에만 걸었는데,
`touchBall()` 에는 **소유하지 않은 공**을 첫 터치로 차는 별도 경로가 있다.
한 경기 20슛에 `shoot` 포즈가 한 번도 안 나왔다.

**5-1. 장수를 바꾸면 뒤 포즈가 전부 밀린다.** `run` 을 4장에서 2장으로
줄이자 그 뒤 11개 포즈의 시작 칸이 모두 -2 만큼 이동했다. 손으로 옮기면
옆 포즈나 빈 칸을 그리는데 화면에는 그럴듯해서 알아채기 어렵다.
**`POSES` 표를 생성기가 직접 `09-sprites.js` 에 박게 바꿨다.**

**5. 지속 포즈가 프레임 0 에 굳었다.** `tackle`·`block` 은 `poseT` 가
아니라 `tackleT`/`blockT` 로 돈다. `poseFrame()` 이 그걸 몰라 17·18·20번
칸이 한 번도 안 그려졌다. `POSE_TIMER` 로 연결했고, 태클·블록 지속시간을
`TACKLE_T`/`BLOCK_T` 상수로 빼 리터럴 중복도 없앴다.

## 프레임을 무엇이 돌리나

장수가 2 이상인 포즈는 **진행도를 낼 근거가 반드시 있어야 한다.**

| 포즈 | 근거 |
|---|---|
| `walk` `run` | `p.stride` — 시간이 아니라 이동 거리. `POSE_STRIDE` 로 포즈마다 다르다 (걷기 0.35m, 달리기 1.1m) |
| `kick` `shoot` `header` `deflect` `gk-dive` `gk-punt` | `p.poseT` (`POSE_DUR`) |
| `tackle` `block` | `p.tackleT` / `p.blockT` (`POSE_TIMER`) |
| `gk-claim` | 공까지의 거리 — 타이머가 없다 |

## 검증 `완료`

- 셀프테스트 50항목 통과. **결정론 검사가 통과한다** — `poseT`·`stride` 를
  넣은 뒤에도 같은 시드의 경기 결과가 그대로다.
- `poseFramesReachable` 이 「함정 5」를 잡는다. `POSE_TIMER` 를 비우고
  돌려보니 `tackle[1] tackle[2] block[1]` 을 정확히 짚었다.
- 한 경기를 끝까지 돌려 13개 중 10개 포즈가 실제로 나오는 것을 봤다.
  `charge` 는 사람 입력 전용, `gk-claim`·`header` 는 드물어 한 경기에서
  안 나올 수 있다 — 연습 모드에서 따로 확인했다.
- 가로·세로 화면 모두 확인. 세로에서 필드 +x 를 향한 선수의 어깨가 화면
  가로로 눕는다 — 경기장과 함께 돈다는 뜻이다.
