# 공중 플레이 — 밸런스 이동 기록

**상태: 측정 기록.** (2026-08-03)

`aerial-play.md` 구현이 밸런스를 얼마나 움직였는지만 남긴다.
**되돌리지 않는다** — `aerial-play.md` 「재밸런싱 단계는 두지 않는다」.

## 왜 기록만 하나

현실 계측치 전환(2026-08-02)에서 맞춘 밸런스가 공중 플레이로 흔들린다.
사용자 결정에 따라 승률·득점 목표에 맞추는 튜닝을 하지 않으므로,
흔들린 채로 두고 이동량만 남긴다.

## 측정 조건

```bash
node tools/soccer-sim.js -n 200
```

기준선은 `balance.md` 「5단계 최종 기준선」. 시드 1, 봇 수준 보통,
골목 FC 대 골목 FC, 10분 경기.

높이 게이트가 발 높이로 서 있는데 헤딩이 없어서 경기의 4분의 1 동안
아무도 공을 건드리지 못했다. **수비가 슛을 막지 못한 것**(블록 60% 감소)이
슛 성공률 상승과 득점 증가의 주원인이다. 로프트를 넣은 골킥이 통제 불능으로
날아가 다시 골라인을 넘는 자기증식 루프도 함께 생겼다.

## 2·3단계 이후

**아직 측정하지 않았다.** 사용자 지시로 해당 구현에서는 셀프테스트와
200경기 회귀를 돌리지 않았다. 다음 작업에서 같은 조건으로 재측정해
이 문서에 표를 한 개 더 붙인다.

측정할 때 함께 볼 지표 — 경기당 헤딩·크로스·몸튕김·GK 하이볼 처리
횟수(`matchStats.headers` / `crosses` / `deflections` / `gkClaims`)와
헤딩 득점(`headGoals`).

예상되는 방향은 `aerial-play.md` 「밸런스 영향」에 적었다.
