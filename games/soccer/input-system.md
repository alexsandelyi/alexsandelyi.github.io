# 조작과 플레이 감

**상태: 전부 제안.** 미측정.

가장 먼저 구현한다. 규칙을 아무리 정교하게 만들어도 공을 다루는 느낌이
없으면 의미가 없고, 태클은 파울(`match-rules.md`)의 전제조건이라 순서상으로도
앞에 온다.

## 공 소유 상태

`baseline.md` 에 적은 대로 `ball.owner` 는 선언만 되어 있다. 이 필드를 살린다.

선수 반경 안에 공이 들어오고 **상대 속도가 낮으면** 트래핑 — 공이 선수 앞
일정 거리에 붙어 함께 움직인다.

```
if (dist < TRAP_R && relSpeed < TRAP_V) ball.owner = p
```

| 규칙 | 값(제안) | 근거 |
|---|---|---|
| 소유 중 최고속도 | `P_MAX × 0.88` | 드리블의 비용. 공 없는 수비수가 따라잡을 근거 |
| 재소유 쿨다운 | 0.35초 | 차고 곧바로 자기가 다시 잡으면 패스가 무의미해진다 |
| 소유 해제 | 태클 성공 / 강한 접촉 / 킥 | — |

**깨지는 것:** `collide()` 전면 재작성. 현재의 "닿으면 무조건 찬다" 가
"소유 중이면 붙이고, 아니면 경합" 으로 바뀐다. 승률이 크게 흔들리므로
이 단계 끝에서 재측정이 필수다.

## 조준

슛·패스 방향을 **스틱/키 입력 방향**으로 정한다.

입력이 없으면 현재처럼 골문 자동 조준으로 폴백한다. 모바일에서 이동과
조준을 동시에 하기 어렵기 때문이다.

- 조준에 정확도 오차를 넣는다. 능력치(`team-tactics.md`)와 연결되고,
  먼 거리 슛이 자동으로 어려워진다.
- `aimAt()` 은 AI 전용으로 남는다.

## 액션

현재 2개(슛/패스) → 4개.

| 액션 | 키보드 | 내용 |
|---|---|---|
| 슛 | Space | 길게 누르면 파워 충전. 짧게 = 낮고 빠른 슛 |
| 짧은 패스 | Shift | 가장 좋은 동료에게. 현재 `passTarget()` 개선 |
| 스루패스 | Ctrl (가칭) | 동료의 **진행 방향 앞 공간**으로. 침투와 짝 |
| 태클 | Space (공 없을 때) | 슛 버튼 재사용 |

`passTarget()` 은 현재 "앞쪽 40단위 이상, 거리 120 이상" 만 본다.
상대 위치를 보지 않아 수비수 정면으로 패스한다. 패스 경로상의 상대를
비용으로 넣는다.

### 모바일 버튼

버튼 4개는 엄지에 과하다. **공 소유 여부로 버튼 2개의 의미를 바꾼다.**

```
소유 중   [ 슛 ] [ 패스 ]
비소유    [ 태클 ] [ 선수전환 ]
```

라벨을 화면에서 함께 바꿔 표시한다. 바뀌는 것이 보이지 않으면 혼란만 준다.

스루패스는 모바일에서 패스 롱프레스로 대체한다.

## 수동 선수 전환

전환 버튼을 추가한다. 누를 때마다 공 기준 가까운 순서로 순환.

자동 전환(`pickControlled()`)은 유지하되, **수동으로 잡은 직후
약 1.2초는 자동 전환을 막는다.** 그러지 않으면 눌러도 곧바로 되돌아간다.

## 스프린트와 체력

스프린트(속도 `×1.25`)를 체력 게이지로 제한한다. 무제한이면 항상 누르고
있게 되어 없는 것과 같다.

**미결:** 3분 경기에서 체력이 유의미하게 닳는가. 전·후반제
(`match-rules.md`)로 경기 시간이 늘어난 뒤에 도입 여부를 재검토한다.
그때까지 스프린트는 구현하되 체력 소모는 0으로 둔다.

## 검증 기준

- 소유 → 드리블 → 패스 → 재소유가 끊기지 않고 이어진다.
- 스틱 방향과 슛 방향이 일치한다 (세로 화면 회전 포함).
- 수동 전환 직후 자동 전환이 선수를 뺏지 않는다.
- 시뮬레이션 재측정에서 목표 승률 73/53/23%, 경기당 5~6골 복원.

## 미결

- 파워 충전 슛은 모바일에서 "누르고 있는 동안 이동 불가" 문제가 있다.
  탭 = 일반 슛 / 롱프레스 = 강슛 으로 충분한가?
- 트래핑 거리를 고정으로 둘 것인가, 진행 속도에 비례시킬 것인가.
