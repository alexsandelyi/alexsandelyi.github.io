# 공의 높이 — 물리와 표현

**상태: 구현 완료.** (2026-08-03)

공에 `z` 축을 넣는다. 지금 공은 당구공처럼 지면만 굴러다닌다.
게임플레이(킥 높이 제어·헤딩·공중 경합)는 `aerial-play.md` 를 따른다.

## 지금 상태

```js
const ball = { x, y, vx, vy, owner, lastTouch, freeCd, ... }   // z 없음
```

중력도 바운스도 없다. `drawBall()` 의 그림자는 `ball.x + r*.24` 고정
오프셋이라 **공에서 절대 떨어지지 않는다** — 높이 표현이 아니라 드롭섀도다.

**크로스바가 없다.** 골 판정은 `inGoalMouth(y)` 로 좌우 폭만 본다.
현실 계측치로 골문 폭을 7.32m 까지 줄였는데 높이는 무한대다.
10m 위로 뜬 슛이 골로 들어간다.

슛 파워(`shootCharge`)는 속도만 바꾼다 — `SHOOT_V × (0.62~1.00)`.
세게 차면 빨라질 뿐 뜨지 않아서 크로스·칩·로빙 패스가 존재할 수 없다.

## 상태 확장

```js
ball.z    // 지면 높이, 논리단위 (0 = 지면). 1m = 20단위
ball.vz   // 수직 속도, 단위/초
```

`ball.owner` 가 있는 동안(드리블)은 `z = 0` 으로 고정한다.

## 물리 상수

| 상수 | 값 | 실세계 |
|---|---|---|
| `GRAVITY` | **196** | 9.81 m/s² |
| `CROSSBAR` | **48.8** | 2.44m 규정 |
| `BOUNCE_Z` | **0.5** | 잔디 반발. 튈 때마다 절반 |
| `BOUNCE_XY` | **0.8** | 바운스 시 수평 속도 잔존 |
| `ROLL_A` | **24** | 1.2m/s². 잔디 구름 저항 (Crr 0.122) |
| `AIR_K` | **0.000677** | 공기 저항 계수. 15m/s 에서 3.05m/s² |
| `GROUND_EPS` | **1.0** | 0.05m 이하면 지면으로 본다 |

지면 판정은 `z <= GROUND_EPS && vz <= 0`. 이때 `vz` 를 0으로 죽이고
구름저항으로 넘긴다. 안 그러면 미세 바운스가 영원히 남는다.

## 적분

`updateBall()` 의 자유 구간에 넣는다.

```
vz -= GRAVITY * dt
z  += vz * dt
if (z <= 0) {
  z = 0
  if (|vz| > 지면판정속도) { vz = -vz * BOUNCE_Z; vx,vy *= BOUNCE_XY }
  else vz = 0
}
감속 a = (z > GROUND_EPS ? 0 : ROLL_A) + AIR_K·v²
        속도 벡터 반대 방향으로 적용 (공중이면 vz 포함)
```

### 감쇠 모델 — 상수 + v² (2026-08-03 교체)

전에는 초당 배율 하나(`v *= 0.82^dt`)로 뭉갰다. 그러면 감속이 속도에
비례해서, 빠를 때는 그럴듯하지만 **느릴 때 너무 안 멈춘다.** 54km/h
땅볼이 74m 를 20.6초에 걸쳐 굴러갔고 그중 40m 가 마지막 17초의 느린
꼬리였다.

현실은 두 항의 합이다 — 속도와 무관한 **구름 저항**과 속도 제곱의
**공기 저항**. 그대로 옮겼다.

```
지면  a = ROLL_A + AIR_K·v²
공중  a =          AIR_K·v²      (구름 저항 없음)
```

`AIR_K` 는 실제 축구공에서 유도했다 — `k = 0.5·ρ·Cd·A/m`,
지름 0.22m·무게 0.43kg·Cd 0.25·공기밀도 1.225 → 0.01354 /m.
논리단위로는 `k/M`.

`ROLL_A` 는 구름저항 계수에서 온다 — `a = Crr·g`. 잔디 위 `Crr` 은
0.05~0.15 다. 처음 0.6m/s²(Crr 0.061)로 잡았더니 공이 너무 잘 굴러
**1.2m/s²(Crr 0.122)로 올렸다**(2026-08-03).

**공기 저항은 수직 성분에도 건다.** 그래서 정점이 진공 포물선보다 낮다.

교체 효과 (54km/h 땅볼):

| | 이전 (지수) | 상수+v², Crr 0.061 | 지금 (Crr 0.122) |
|---|---|---|---|
| 거리 | 74.4m | 66.6m | **46.7m** |
| 시간 | **20.6초** | 12.4초 | **7.7초** |

해석 예측 46.7m / 7.9초와 일치한다.

느린 공의 감속이 실제로 커진다 — 2m/s 공이 3초 안에 3m 안쪽에서 선다.
전 모델은 10초에 8.8m 를 갔다.

### 로프트와 도달 거리

수평 300단위/초 고정으로 `vz` 를 훑은 실측(교체 후):

| `vz` | 정점 | 거리 | 바운스 |
|---|---|---|---|
| 0 (땅볼) | 0m | **46.7m** | 0 |
| 100 | 1.16m | 31.0m | 3 |
| 250 | 6.62m | 43.7m | 4 |
| 400 | 15.0m | **51.4m** | 5 |

구름 저항을 올린 뒤로는 큰 로프트가 땅볼을 다시 앞선다(`vz` 400 에서
51.4m 대 46.7m). 공중에는 구름 저항이 없기 때문이다. 낮은 로프트는
여전히 손해다 — 체공이 짧아 바운스 손실만 먹는다.

게임에서 로프트의 값어치는 **거리가 아니라 상대를 넘기는 것**이다.
비행 중인 공은 높이 게이트에 걸려 발로는 못 건드린다(`aerial-play.md`).
크로스와 칩이 존재하는 이유가 그것이다.

## 그리기

높이의 주된 단서는 크기가 아니라 **그림자 분리**다. 둘 다 쓴다.

| 요소 | 규칙 |
|---|---|
| 그림자 | 지면 `(x, y)` 에 그대로. 높을수록 작고 옅게 |
| 공 | 화면 기준 위로 `z × 0.5` 만큼 띄워 그린다 |
| 공 크기 | `drawRadius(R_BALL) × (1 + z / 200)`, 최대 1.8배 |

`z / 200` 은 10m 에서 2배가 되는 비율이고 1.8배에서 자른다.
현실보다 과장이지만 톱다운에서 높이를 읽으려면 필요하다. 측정이 아니라
가독성 값이므로 브라우저에서 보고 조정한다.

### 회전 함정 — 반드시 지킨다

세로 화면에서 경기장을 90° 돌린다. **높이 오프셋을 필드 좌표로 그대로
쓰면 세로 화면에서 공이 위가 아니라 옆으로 뜬다.**

현재 변환은 `ctx.transform(0, -s, s, 0, 0, 0)` 이다. 이는
`화면x = s·필드y`, `화면y = -s·필드x` 로 사상하므로 **화면 위쪽은
필드 +x 방향**이다. 가로 화면(`ctx.scale(s, s)`)에서는 필드 -y 다.

```js
const lift = ball.z * 0.5;
const ox = view.rot ?  lift : 0;
const oy = view.rot ?  0    : -lift;
```

입력 벡터를 같이 돌려야 했던 것과 같은 종류의 함정이다
(`CLAUDE.md` 「좌표계」 참조). 세로 화면에서 실제로 확인한다.

## 크로스바

골 판정에 높이를 넣는다.

```
골 = 골라인 통과 && inGoalMouth(y) && z < CROSSBAR
```

`outOfPlay()` 의 골 분기와, 드리블로 골라인을 넘는 경로
(`updateBall()` 의 `crossedGoal`)에 모두 적용한다. 드리블 중에는
`z = 0` 이므로 후자는 자동으로 만족한다.

**크로스바를 맞고 튀는 처리는 1차에서 넣지 않는다.** 바 위로 넘어가면
골킥, 안으로 들어가면 골. 골대 기둥·크로스바 반사는 별도 작업이다.

## 다른 코드에 미치는 영향

| 위치 | 처리 |
|---|---|
| `resetPositions` / `beginSetpiece` | `z = vz = 0` 초기화 |
| `releaseBall` / `kickOwned` | `vz` 를 함께 정한다 (`aerial-play.md`) |
| `collide` | 높이 게이트 추가 (`aerial-play.md`) |
| `takePossession` | 낮은 공만 트래핑 |
| 미니맵 | 높이는 표시하지 않는다. 위치만 |
| `tools/soccer-sim.js` | 셀프테스트에 포물선·바운스·크로스바 검사 추가 |

## 검증 기준

셀프테스트 항목명을 괄호에 적었다 (`node tools/soccer-sim.js --self-test`).

- 한 프레임 감속이 `ROLL_A + AIR_K·v²`(지면) / `AIR_K·v²`(공중)와
  일치한다 (`dragModel`).
- 공기 저항이 수직에도 걸려 정점·체공이 진공 포물선보다 낮고 짧되,
  60~100% 안에 머문다 (`ballistic`).
- 느린 공(2m/s)이 4초 안에 5m 안쪽에서 선다 (`slowBallStops`).
  지수 감쇠의 긴 꼬리가 사라졌는지 보는 항목이다.
- 공중 감속이 지면보다 정확히 `ROLL_A` 만큼 작다 (`airLighterThanGround`).
- 바운스마다 정점이 크게 줄고 결국 완전히 멈춘다 (`bounceDecay`).
- 크로스바 위로 넘어간 슛이 골이 아니다 (`crossbar`).
- **세로 화면에서 공이 화면 위쪽으로 뜬다** (옆으로 새지 않는다).
  브라우저로 확인한다.
- 그림자와 공이 분리돼 높이가 눈으로 읽힌다. 브라우저로 확인한다.
