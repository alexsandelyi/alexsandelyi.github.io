## 확장이 얹히는 지점

설계가 여기에 붙는다. 각 항목이 어느 문서로 이어지는지 표시했다.

### 터치라인과 골라인은 아웃이다

`updateBall()`이 마지막 터치를 기준으로 스로인·골킥·코너를 시작한다.
세트피스는 하나의 `setpiece` 상태로 처리한다. → `match-rules.md`

### 공 소유 상태가 있다

`ball.owner`를 실제로 사용한다. 느린 공은 트래핑하고 소유 중 최고속도는
`P_MAX × 0.88`, 킥 후 재소유 쿨다운은 0.35초다. → `input-system.md`

### 슛과 패스를 조준한다

사람은 이동 입력 방향으로 조준하고 입력이 없으면 `aimAt()`으로 폴백한다.
AI는 기존 자동 조준을 유지한다. → `input-system.md`

### 선수 전환은 자동과 수동이다

`pickControlled()`의 자동 전환을 유지하고, 공과 가까운 순서의 수동 순환과
1.2초 자동 전환 잠금을 추가했다. → `input-system.md`

### 공격 방향은 팀 색과 분리됐다

`attackDir[side]`가 방향을 담당하고 색상은 `side`에 남는다.
하프타임에 두 방향을 뒤집는다. → `match-rules.md`

## 난이도 파라미터

```
              speed  react  aimErr  shoot   gk
쉬움           0.86   0.65    200    0.88   0.55
보통           0.88   0.28    100    0.88   0.85
어려움         0.92   0.12     40    0.88   1.00
```

`speed` 는 좁은 범위(0.86~0.92)다. 과거 작은 표본에서 보인 계단은
2026-07-31 각 값 200경기 스윕에서 재현되지 않았다 (`balance.md`).
난이도 차이는 `speed`, `react`(반응 지연), `aimErr`(조준 오차),
`gk`(골키퍼 반응)를 포함한 전체 조합의 결과다.

우리 팀 AI 동료는 난이도와 무관하게 항상 `LEVELS[1]`(보통) + 속도 `0.92`.

## 상태 기계

```
title ──→ play ──→ goal ──→ play      (시간 남음)
            │        └────→ end       (시간 종료)
            └────────────→ end
end ──→ play (다시 하기) | title (처음으로)
```

`state` 는 이 4개뿐이다. 세트피스를 넣으면 여기에 상태가 추가된다.
→ `match-rules.md`
