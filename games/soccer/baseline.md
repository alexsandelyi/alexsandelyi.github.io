## 확장이 얹히는 지점

설계가 여기에 붙는다. 각 항목이 어느 문서로 이어지는지 표시했다.

### 터치라인과 골라인은 아웃이다

`updateBall()`이 마지막 터치를 기준으로 스로인·골킥·코너를 시작한다.
세트피스는 하나의 `setpiece` 상태로 처리한다. → `match-rules.md`

### 공 소유 상태가 있다

`ball.owner`를 실제로 사용한다. 느린 공은 트래핑하고 소유 중 최고속도는
`P_MAX × 0.88`, 킥 후 재소유 쿨다운은 0.35초다. → `input-system.md`

### 슛과 패스를 조준한다

사람은 이동 입력 방향으로 조준하고 입력이 없으면 `aimAt()`으로 폴백한다.
AI는 기존 자동 조준을 유지한다. → `input-system.md`

### 선수 전환은 자동과 수동이다

`pickControlled()`의 자동 전환을 유지하고, 공과 가까운 순서의 수동 순환과
1.2초 자동 전환 잠금을 추가했다. → `input-system.md`

### 공격 방향은 팀 색과 분리됐다

`attackDir[side]`가 방향을 담당하고 색상은 `side`에 남는다.
하프타임에 두 방향을 뒤집는다. → `match-rules.md`

### 팀과 전술이 물리에 반영된다

선수 능력치가 속도·킥·태클·체력·선방을 바꾸고, 수비선·압박·폭·추격
인원이 `slotTarget()`과 추격자 선택을 바꾼다. → `team-tactics.md`

## 난이도 파라미터

```
              speed  react  aimErr  shoot   gk
쉬움           1.00   0.90    280    0.75   0.35
보통           1.00   0.28    100    0.88   0.85
어려움         1.00   0.15     55    0.88   0.95
```

난이도 `speed`는 모두 1이다. 물리 속도는 팀 능력치로 이관했다.
난이도 차이는 `react`, `aimErr`, `shoot`, `gk`와 1P 보조 조합의 결과다.

1P 상대 이동 배수는 모두 1, 조작 선수 슛 배수는 `1.18/1.40/1.18`이다.
보통은 태클 성공 보조 `+0.28`, 우리 GK 접촉 반경 `×1.35`를 쓴다.
기준 팀 회귀는 `balance-expansion.md`에 기록한다.

우리 팀 AI 동료는 난이도와 무관하게 항상 `LEVELS[1]`(보통)을 쓴다.

## 상태 기계

```
title → setpiece ↔ play → goal → setpiece
          │         ├────→ halftime → setpiece
          └─────────┴────→ end
end → play (다시 하기) | title (처음으로)
```

`state`는 `title/play/goal/setpiece/halftime/end` 여섯 개다.
→ `match-rules.md`
