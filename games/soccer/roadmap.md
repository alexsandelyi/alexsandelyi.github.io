# 구현 순서와 결정

**상태: 0~6단계 완료.** 계획한 확장 구현과 단계별 검증을 마쳤다.

## 순서

각 단계 끝에서 **반드시 밸런스 재측정**을 한다 (`balance.md`).
앞 단계가 승률을 바꿔놓기 때문이다.

| 단계 | 내용 | 문서 | 완료 기준 |
|---|---|---|---|
| 0 | 밸런스 도구·기준선·`speed` 스윕 | `balance.md` | **완료** (2026-07-31) |
| 1 | 조작 — 소유·조준·태클·수동 전환 | `input-system.md` | **완료** (2026-07-31) |
| 2 | 규칙 — 아웃·세트피스·전후반 | `match-rules.md` | **완료** (2026-07-31) |
| 3 | 규칙 — 오프사이드·파울·옐로 | `match-rules.md` | **완료** (2026-07-31) |
| 4 | 팀·전술 | `team-tactics.md` | **완료** (2026-07-31) |
| 5 | 토너먼트 + 승부차기 | `game-modes.md` | **완료** (2026-07-31) |
| 6 | 리그·시즌·기록 | `game-modes.md` | **완료** (2026-07-31) |

순서의 근거는 의존 관계다 (`README.md` 다이어그램).

- 태클(1)이 없으면 파울(3)이 성립하지 않는다.
- 공 소유(1)가 없으면 점유율(6)과 경합 능력치(4)가 의미를 갖지 못한다.
- 조준(1)과 세트피스(2)가 없으면 승부차기(5)를 만들 수 없다.
- 팀이 동일하면(4 이전) 토너먼트(5)가 의미 없다.

## 공개

**전 단계 완료 후 1회.** 중간 상태는 로컬 커밋으로만 보관한다.

루트 `AGENTS.md` 「축구 게임 공개 시점」과 `CLAUDE.md` 를 따른다.
최종 검증 후 변경 내용과 검증 결과를 보고하고, 그 1회의 `git push` 승인을
명시적으로 받는다.

## 결정된 것

### 파일 분할 — 코드 파일 500줄 제한 `확정` (2026-08-03 교체)

전에는 "단일 파일 유지, 3000줄에서 재검토" 였다. 2,932줄에 이르러
사용자 결정으로 **코드 파일 500줄 제한**으로 바꿨다.

게임은 `games/soccer/js/` 의 11개 파일로 나누고 `index.html` 이 클래식
`<script src>` 로 순서대로 불러온다. **ES 모듈이 아니다** — 클래식
스크립트는 전역 스코프를 공유해서 빌드도 import 도 필요 없고, 측정
도구가 파일을 순서대로 실행할 수 있다.

자세한 규칙과 함정은 `CLAUDE.md` 「코드 파일 500줄」 참조.

### 오프사이드 — 난이도 연동만 `확정`

쉬움 = 끄기 / 보통 = 켜기 / 어려움 = 켜기. **별도 on/off 설정은 두지
않는다.** 설정이 늘면 UI 와 조합 테스트가 함께 늘어난다.

되돌리기 쉬운 결정이다 — 나중에 토글이 필요해지면 그때 추가한다.

### 레드카드 — 후속 규칙 확장으로 보류 `확정`

퇴장은 인원 가변 처리라 11명 고정 배열을 쓰는 `FORMATION` 전반에
파급된다. 3단계에서는 옐로까지만 넣고, 포메이션 테이블화(4단계) 이후로
미룬다.

### 목표 승률 — 기준 팀 기준으로 80/53/23% `확정`

**쉬움을 73% → 80% 로 고쳤다** (2026-07-31 사용자 결정).
독립 난수 기준선의 실측 81.5%가 목표와 맞는다. 봇 결과를 사람의 하한이나
예측값으로 해석하지 않으며, 실제 사용자 승률은 직접 플레이테스트로 확인한다.

4단계에서 팀마다 강함이 달라지면 단일 목표가 성립하지 않는다.
**평균 등급의 기준 팀끼리 붙었을 때**의 승률로 목표를 재정의한다.
회귀 판정도 이 조건에서만 한다.

## 결정

### 1. 난이도와 팀 강함의 축 분리

`team-tactics.md` 참조. 난이도 = AI 반응(`react`/`aimErr`/`gk`),
팀 = 능력치로 나누고 `speed`를 능력치로 이관한다.

**두 축을 분리한다.**

과거 30경기 관찰에서는 `speed`가 `0.87` 근처에서 계단처럼 보였다.
0단계 각 200경기 스윕에서는 가장 큰 인접 변화가 8.5%p였고 인접 신뢰구간이
모두 겹쳐 계단이 재현되지 않았다 (`balance.md`).

1단계 후 스윕에서도 최대 인접 변화는 11.5%p였고 해당 신뢰구간이 겹쳤다.
구현 전·후 모두 계단이 재현되지 않았으므로 4단계에서 이관한다.
