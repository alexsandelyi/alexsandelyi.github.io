# 축구 게임 작업 규칙

이 파일은 `games/soccer/`와 모든 하위 경로에 적용한다. 저장소 루트의
`AGENTS.md` 규칙도 함께 적용하며, 충돌할 때는 더 안전하고 구체적인 규칙을
따른다.

## 설계 문서를 두지 않는다 (2026-08-13)

- `games/soccer/*.md` 설계 문서 24개를 지웠다. 코드가 3062줄이라 직접 읽을
  수 있고, 낡은 문서가 현재 사실인 척하는 쪽이 더 위험했다.
- **새 `.md` 를 만들지 않는다.** 알아야 할 사실은 이 파일이나 같은 폴더의
  `CLAUDE.md`, 또는 코드 주석에 적는다.
- 코드에서 복원할 수 없는 두 가지 — **밸런스 기준선 수치**와 **스프라이트
  에서 실패한 방법** — 은 `CLAUDE.md` 로 옮겼다. 그쪽을 본다.
- 지운 문서는 git 에 남아 있다 (`git show 267d550:games/soccer/balance.md`).
  꺼내 보되 **현재 사실로 믿지 않는다.**
- 구현했으면 브라우저에서 실제로 열어 도는지 확인한다 — 수치를 뽑는 것은
  아래 「밸런스 측정」에 걸린다.

## 밸런스 측정 — 사용자가 직접 한다 (2026-08-05)

- **시뮬레이션 배치와 실측을 먼저 돌리지 않는다.** `soccer-sim.js -n ...`,
  `soccer-lab.js`, 브라우저 실측 표는 사용자 몫이다. 요청받았을 때만
  실행하고 "측정해서 확인하겠다"고 제안하지 않는다.
- `--restamp`(`js/` 수정 시 필수)와 `--self-test`(통과/실패 검사)는
  계속한다. 수치를 뽑는 게 아니라 깨진 것을 잡는 장치다.
- 측정하지 않은 값은 **모른다고 적는다.** 확인이 필요하면 실행하지 말고
  명령어와 볼 지점을 알려주고 넘긴다.
- 승률·득점 목표에 맞춘 상수 튜닝(재밸런싱)은 하지 않는다.
- 도구와 기준선은 유지한다 — 판정에 쓸 때는 난이도별 200경기 이상이
  필요하고, 30경기는 빠른 오류 확인에만 쓴다.
- 과거 30경기에서 보인 `speed` 0.87 부근의 급변은 각 값 200경기 스윕에서
  재현되지 않았다.

## 코드 파일 500줄 제한

- 코드 파일(`.js`, `.html`, `.py`)은 **500줄을 넘지 않는다**. 설계 문서는
  200줄이다.
- 선수 스프라이트는 `tools/sprite-gen.py` 가 만든다. PNG 를 손으로 고치지
  않는다 — 다음 생성 때 사라진다. 시트를 다시 만들면 `--restamp` 까지
  이어서 돌린다 (`SPRITE_V` 가 바뀌기 때문).
- 게임 코드는 `games/soccer/js/NN-이름.js` 로 나누고 `index.html` 이
  클래식 `<script src>` 로 순서대로 부른다. **ES 모듈로 바꾸지 않는다** —
  전역 스코프 공유가 깨지면 빌드가 필요해지고 측정 도구도 못 쓴다.
- **로드 순서가 의존 순서다.** 호이스팅은 파일 안에서만 동작하므로 앞
  파일의 최상위 코드가 뒤 파일의 함수를 참조하면 안 된다. 콜백이나
  화살표로 감싸 호출 시점에 찾게 한다.
- 파일마다 `'use strict';` 를 둔다. 독립 스크립트라 파일마다 필요하다.
- 줄 수 확인:

```bash
for f in games/soccer/js/*.js tools/*.js tools/*.py; do
  c=$(wc -l < "$f"); [ "$c" -gt 500 ] && echo "초과: $f ($c)"
done
```
