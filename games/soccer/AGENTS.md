# 축구 게임 작업 규칙

이 파일은 `games/soccer/`와 모든 하위 경로에 적용한다. 저장소 루트의
`AGENTS.md` 규칙도 함께 적용하며, 충돌할 때는 더 안전하고 구체적인 규칙을
따른다.

## 설계 파일 위치와 형식

- 설계 문서는 모두 `games/soccer/` 바로 아래에 Markdown 파일로 작성한다.
- 설계 문서를 별도의 `docs/`, `design/` 또는 다른 하위 디렉터리에 두지
  않는다.
- 파일 이름은 내용을 드러내는 영문 소문자 kebab-case를 사용한다.
  예: `match-rules.md`, `player-ai.md`, `input-system.md`
- 한 파일에는 하나의 주요 주제만 다룬다.
- 여러 설계 파일이 생기면 `games/soccer/README.md`를 목차로 사용하고 각
  문서의 역할과 관계를 한 줄씩 기록한다.

## 200줄 제한

- 설계 파일은 빈 줄과 코드 블록을 포함한 물리적 줄 수가 **200줄을
  넘으면 안 된다**.
- 200줄을 초과할 내용은 글자를 억지로 압축하지 말고 책임이나 주제별로
  별도 설계 파일에 나눈다.
- 문서를 수정한 뒤에는 다음 명령으로 줄 수를 확인한다.

```powershell
Get-ChildItem -LiteralPath '.\games\soccer' -File -Filter '*.md' |
  Where-Object { $_.Name -ne 'AGENTS.md' } |
  ForEach-Object {
    [PSCustomObject]@{
      File = $_.FullName
      Lines = (Get-Content -LiteralPath $_.FullName).Count
    }
  }
```

- 줄 수가 200을 넘는 설계 파일이 있으면 설계 작업을 완료한 것으로
  보고하지 않는다.

## 설계 문서 내용

- 각 문서에는 목적, 범위, 핵심 규칙, 데이터나 상태의 흐름, 예외 상황,
  검증 기준을 필요한 만큼 기록한다.
- 확정된 결정과 검토 중인 제안 또는 TODO를 명확히 구분한다.
- 코드와 반드시 일치해야 하는 수치, 좌표계, 상태 전이와 인터페이스를
  모호한 표현 없이 적는다.
- 구현 코드를 길게 복사하지 않는다. 설계를 설명하는 데 필요한 짧은
  의사코드와 인터페이스 예시만 사용한다.
- 난이도와 밸런스 수치는 추측으로 확정하지 않는다. 시뮬레이션 조건과
  측정 결과를 함께 기록한다.

## 설계와 구현의 동기화

- 중요한 동작이나 게임 규칙을 구현하기 전에 관련 설계 문서를 먼저
  작성하거나 함께 갱신한다.
- 구현이 설계와 달라졌다면 같은 작업에서 문서를 갱신하고, 차이가 남은
  상태로 완료를 선언하지 않는다.
- 문서 변경만으로 구현이 검증됐다고 판단하지 않는다. 브라우저에서 실제로
  열어 도는지 확인한다 — 수치를 뽑는 것은 아래 「밸런스 측정」에 걸린다.

## 밸런스 측정 — 사용자가 직접 한다 (2026-08-05)

- **시뮬레이션 배치와 실측을 먼저 돌리지 않는다.** `soccer-sim.js -n ...`,
  `soccer-lab.js`, 브라우저 실측 표는 사용자 몫이다. 요청받았을 때만
  실행하고 "측정해서 확인하겠다"고 제안하지 않는다.
- `--restamp`(`js/` 수정 시 필수)와 `--self-test`(통과/실패 검사)는
  계속한다. 수치를 뽑는 게 아니라 깨진 것을 잡는 장치다.
- 측정하지 않은 값은 **모른다고 적는다.** 확인이 필요하면 실행하지 말고
  명령어와 볼 지점을 알려주고 넘긴다.
- 승률·득점 목표에 맞춘 상수 튜닝(재밸런싱)은 하지 않는다.
- 도구와 기준선은 유지한다 — 판정에 쓸 때는 난이도별 200경기 이상이
  필요하고, 30경기는 빠른 오류 확인에만 쓴다.
- 과거 30경기에서 보인 `speed` 0.87 부근의 급변은 각 값 200경기 스윕에서
  재현되지 않았다.

## 코드 파일 500줄 제한

- 코드 파일(`.js`, `.html`)은 **500줄을 넘지 않는다**. 설계 문서는 200줄이다.
- 게임 코드는 `games/soccer/js/NN-이름.js` 로 나누고 `index.html` 이
  클래식 `<script src>` 로 순서대로 부른다. **ES 모듈로 바꾸지 않는다** —
  전역 스코프 공유가 깨지면 빌드가 필요해지고 측정 도구도 못 쓴다.
- **로드 순서가 의존 순서다.** 호이스팅은 파일 안에서만 동작하므로 앞
  파일의 최상위 코드가 뒤 파일의 함수를 참조하면 안 된다. 콜백이나
  화살표로 감싸 호출 시점에 찾게 한다.
- 파일마다 `'use strict';` 를 둔다. 독립 스크립트라 파일마다 필요하다.
- 줄 수 확인:

```bash
for f in games/soccer/js/*.js tools/*.js; do
  c=$(wc -l < "$f"); [ "$c" -gt 500 ] && echo "초과: $f ($c)"
done
```
