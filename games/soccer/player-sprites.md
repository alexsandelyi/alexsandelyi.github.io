# 선수 스프라이트 — 액션 목록과 에셋 규격

**상태: 제안.** 액션 목록은 코드에서 뽑았으므로 `확정`, 규격과 제작
방식은 `미결` 이다. 아래 「미결」을 정한 뒤 만들기 시작한다.

지금 선수는 원 하나다 (`10-draw.js` `drawPlayer`). 색·등번호·조작
테두리만 다르고, 액션 표현은 `blockT > 0` 일 때의 막대 하나뿐이다.

## 액션 목록 `확정`

코드에 이미 있는 상태다. 새로 만드는 개념이 아니다.

### 이동 — 속도 구간 4단계 (`04-physics.js`)

| 포즈 | 조건 | 속도 |
|---|---|---|
| `idle` | 정지 | — |
| `walk` | `SPEED_WALK` | 5km/h |
| `jog` | `SPEED_JOG` | 11km/h |
| `run` | `SPEED_RUN` | 20km/h |
| `sprint` | `SPEED_SPRINT` | 34.2km/h |

`energy <= 0.08` 이면 스프린트가 달리기로 강등된다 (`04-physics.js:91`).
지친 표현이 필요하면 별도 포즈가 아니라 **오버레이**로 얹는다.

### 공 소유·킥

| 포즈 | 플래그 | 쿨다운 |
|---|---|---|
| `dribble` | `ball.owner === p` | 공이 조준 방향 0.61m 앞 |
| `charge` | `shootHeld` / `shootCharge` | 최대 1.05초 |
| `shoot` | `actShoot` | `kickCd` 0.3초 |
| `pass` | `actPass` (`\` 땅볼) | 0.25초 |

`dribble` 은 단독 포즈가 아니라 이동 포즈와 곱해진다 — 「포즈 우선순위」 참조.

조작 중(흰 테두리 + 삼각형), 옐로카드(`p.yellow`), 등번호.

## 방향은 회전으로 푼다 `제안`

**방향별 에셋을 만들지 않는다.** 톱다운이라 위에서 본 선수는 회전해도
자연스럽다. `ctx.rotate` 한 번이면 360° 가 다 나온다. 8방향으로 쪼개면
에셋이 8배가 되고 그만큼 얻는 게 없다.

주의할 점 둘.

- **보는 방향과 가는 방향이 다르다.** `p.aimX/aimY` 와 `p.vx/vy` 가 따로
  있어서 (`08-loop.js:84`) 뒷걸음질·게걸음이 가능하다. 스프라이트는
  `aim` 으로 돌리고, 이동 루프는 진행 방향이 조준의 반대쪽이면 역재생한다.
- **세로 화면.** 경기장을 90° 돌린다. 선수는 경기장과 **같이** 돌린다 —
  등번호(`10-draw.js`)처럼 세우면 안 된다. 세워버리면 선수가 향한
  방향과 그림이 어긋난다.

## 포즈 우선순위 `제안`

플래그가 흩어져 있어 한 프레임에 여러 개가 동시에 참이다. 하나로 접는
함수를 둔다. 그리기 전용이며 물리·AI 는 건드리지 않는다.

```js
function playerPose(p) {          // 09-sprites.js
  if (p.isGK && p.gkClaim)   return 'gk-claim';
  if (p.poseT > 0)           return p.pose;   // 원샷 동작이 재생 중
  if (p.tackleT > 0)         return 'tackle';
  if (p.blockT > 0)          return 'block';
  if (p.shootHeld)           return 'charge';
  return speedPose(p);              // idle / walk / jog / run / sprint
}
```

`dribble` 은 이동 포즈 위에 **공 잡은 팔·다리 레이어**로 얹는다. 별도
포즈로 두면 이동 4단계 × 2 로 늘어난다.

### 쿨다운은 애니메이션 길이가 아니다 `미결`

`headCd` 0.6초는 **연속 헤딩 드리블을 막는 게임 규칙**이지 헤딩 동작이
0.6초라는 뜻이 아니다. `kickCd`, `trapCd` 도 같다. 쿨다운으로 프레임을
고르면 킥 자세로 0.3초를 굳어 있게 된다.

그리기용 타이머 `p.poseT` / `p.pose` 를 따로 둔다. 킥·헤딩·태클이 나갈 때
찍고 `movePlayer()` 에서 `dt` 만큼 깎는다. **물리·AI 에서는 읽지 않는다** —
읽으면 창 크기나 프레임률이 경기 결과를 바꿀 수 있다.

## 규격 `확정`

- **크기** — `DRAW_PLAYER_MIN_PX = 18` 이라 줌아웃하면 지름 18px 까지
  작아진다. **이 크기에서 태클과 헤딩이 구분돼 보여야 한다.** 실루엣이
  전부다. 확대 시를 감안해 원본은 64px 이상으로 그리고 축소해 쓴다.
- **팀 색 4가지** — 홈 `#F58A5E`, 원정 `#F2CE7A`, GK홈 `#8FD1C4`,
  GK원정 `#C9A6E0` (`01-core.js:38`). 프레임마다 4벌을 만들면 4배다.
  **단색 실루엣 + 흑백 디테일 2레이어**로 만들어 색은 코드에서 입힌다.
- **등번호** — 스프라이트에 굽지 않는다. 22명 구분이 전적으로 번호에
  달려 있고, 지금처럼 위에 그리면 회전과 무관하게 세워둘 수 있다.
- **형식** — PNG 스프라이트 시트. 셀 64px, `games/soccer/assets/players.png`.

만드는 방법·프레임 수·구현·함정은 [sprite-pipeline.md](sprite-pipeline.md) 로
나눴다 (2026-08-05, 이 문서가 200줄을 넘어서).
